## Как читать поля

`_fr`, `_en`, `_ru` — три отдельных обычных поля. Никакого JSON в коллекциях контента нет. Text — строка/абзацы, Number — число, Select — выбор из готового списка, Relation — ссылка на запись другой коллекции, File — загрузка файла, URL — веб-адрес. Системные id/created/updated не заполняешь сама.

## project_media — галерея

| Поле | Тип | Что вводить |
|---|---|---|
| project | Relation → projects | к какой работе относится |
| type | Select | image или video |
| position | Number 1–4 | порядок в галерее; 1 = главное медиа |
| image | File, один файл | фотография/рисунок: JPEG, PNG или WebP до 10 МБ |
| media_url | URL | публичная ссылка: видео всегда здесь; изображение тоже может быть ссылкой |
| alt_fr / alt_en / alt_ru | Text | коротко описать изображение для доступности |

Галерея = 1–4 медиа всего. Одно видео максимум, всегда position = 1. Допустимы только видео, только картинки, видео + картинки. Главный элемент — запись с position = 1, отдельного cover нет. На главной и в каталоге берём её же, включая видео. У картинки заполняется image ИЛИ media_url, а не оба. В поле image у видео можно загрузить необязательный постер.

Position не повторяется внутри одной работы. Необязательно заполнять все четыре места. При удалении главного медиа следующему присваивается 1. Будущая админка сделает перестановки кнопками; в системной панели номера пока меняются вручную. Для обмена 1 и 2 используй свободную позицию 3 или 4; если все места заняты, переставим через серверную операцию будущей админки, не удаляя файлы.

Ширину и высоту вручную не вводим. Это исходные пиксели файла, не размер на экране; позже сайт определит их для сетки. Галерея сохраняет пропорции через contain. Очень длинная картинка — целиком с увеличением, без обрезки. На телефоне миниатюры снизу.

Видео в будущем компоненте: autoplay, muted, loop, playsinline; пауза у скрытого слайда и вне экрана. Если браузер блокирует autoplay, показываем ручной запуск. Нужна воспроизводимая ссылка на файл/плеер, а не произвольная страница сайта с видео. Провайдер выбирается позже, пока никаких его служебных полей нет.

Alt не виден рядом с картинкой: это описание для экранного диктора и при недоступном изображении. Например «Три туристические афиши с архитектурой Монбельяра». Caption — необязательная подпись «Финальный рендер», которая видна посетителю. Это разные задачи, не две копии одного текста.

## project_sections — этапы под галереей

| Поле | Тип | Что вводить |
|---|---|---|
| project | Relation → projects | работа |
| position | Number от 1 | порядок этапов, не повторяется внутри проекта |
| title_fr / title_en / title_ru | Text | название этапа: Brief, Concept… |
| description_fr / description_en / description_ru | Text | основное описание этапа |
| detail_image | File | необязательная дополнительная схема/иллюстрация |
| detail_image_mobile | File | необязательный мобильный вариант той же схемы |
| detail_alt_fr / detail_alt_en / detail_alt_ru | Text | описание дополнительной картинки |
| note_fr / note_en / note_ru | Text | необязательная небольшая заметка под картинкой/описанием |
| button_label_fr / button_label_en / button_label_ru | Text | например «Посмотреть сайт» |
| button_url | URL | адрес, куда ведёт кнопка |

Номер 01/02/03 создаст шаблон из порядка — вводить его в заголовок не нужно. Количество этапов не ограничено тремя. Название этапа не повторяет название проекта: например проект Éclovoix, этап Conception. У рисунка может не быть ни одного этапа.

Это минимальная версия без JSON и сложного конструктора. Порядок оформления этапа: название → описание → необязательная иллюстрация → необязательная заметка → необязательная кнопка. Кнопка остаётся настоящей ссылкой в коде. Заметке код задаёт один общий стиль — небольшой приглушённый текст.

Не экспортируй мелкий многоязычный текст целиком в одну широкую картинку: на телефоне он станет нечитабельным и не будет переводиться. Основное содержание остаётся Text. Палитру и простую цепочку можно впоследствии сделать отдельными адаптивными блоками, когда заполняем первые четыре примера. Если схема действительно сложная, detail_image_mobile позволяет дать один мобильный вариант, не три версии для каждого устройства. Изображения схем лучше содержат графику, а подписи идут живым текстом. Если будет нужна локализация самих схем, добавим отдельные языковые изображения до их наполнения; текущие картинки предполагаются без языкового текста.

## SEO: что говорить преподавателю

SEO — не место хранения данных, а то, как сайт отдаёт поисковику читаемые страницы. База хранит редактируемые тексты; Astro должен вывести их в готовый HTML. Необязательные seo_title_* и seo_description_* позволяют настроить поисковый заголовок и краткое описание; если пусто, шаблон возьмёт название и начало обычного описания. Самих полей недостаточно: подключение к странице проекта выполняется на следующем этапе.

Сейчас у статических страниц уже есть title, локализованные описания и html lang; добавлены Open Graph, условные абсолютные canonical и hreflang для реального домена. До домена абсолютные адреса не выдумываем. В Astro config домен берётся из переменной окружения SITE_URL на хостинге/при сборке. Пустые страницы проектов/правовой информации имеют noindex до наполнения; убрать его при реализации этих страниц.

После выбора домена: настроить SITE_URL, добавить sitemap.xml и robots.txt, включить в sitemap только опубликованные страницы, исключить админку/черновики, подключить Google Search Console и проверить индексацию. Локальный localhost не публикуется в Google. Канонический адрес у каждой языковой версии свой, а hreflang связывает FR/EN/RU. Для проектов метаданные должны читаться из соответствующих полей до формирования HTML, а не появляться только после загрузки браузерного JS. Статическая сборка требует пересборки после публикации, либо выбираем серверный рендеринг при интеграции.

Keywords-поле не добавлено: Google не использует meta keywords для индексации или ранжирования. Нужны содержательный текст, понятные названия, доступные изображения и рабочие ссылки. Meta description может использоваться для сниппета, но Google может выбрать другой фрагмент. Появление и позиция в выдаче не гарантируются.

Официальные источники: [Google: метатеги](https://developers.google.com/search/docs/crawling-indexing/special-tags), [Google: сниппеты](https://developers.google.com/search/docs/appearance/snippet), [Google: языковые версии](https://developers.google.com/search/docs/specialty/international/localized-versions), [PocketBase: миграции](https://pocketbase.io/docs/js-migrations/).
